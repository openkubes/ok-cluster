# OpenKubes ok-cluster / `ok` CLI v1.0.1 — release notes (DRAFT)

> **Status: draft, not released.** v1.0.1 is not tagged or published. It becomes the official release only after the gates in `docs/release-process.md`, including lifecycle safety acceptance on authorized disposable infrastructure, and an explicit approval. Until then, builds of this code are acceptance builds named `v1.0.1-rcN`.

v1.0.1 is the first `1.x` release and follows `v0.15.0`; there is no v1.0.0. From now on, ok-cluster releases and the `ok` CLI share one Semantic Version.

## Highlights

- **Same-Plane Talos/KubeVirt lifecycle from the CLI.** `ok up` creates a workload cluster on a prepared management cluster, and `ok destroy <name>` removes it. Both:
  - show the management API identity (API server, CA, kube-system UID) and require typed confirmations;
  - verify the bundled sources before changing anything;
  - never use `KUBECONFIG` or the current kubectl context. (#488, #491, #492, #493, #497)
- **Lifecycle state outside the source tree.** Cluster state and evidence live in `$XDG_STATE_HOME/ok/clusters`, or `~/.local/state/ok/clusters`. (#498, #500)
- **Installable release bundle.** `ok-<version>-<os>-<arch>.tar.gz` contains:
  - the CLI;
  - minimal Git copies of `ok-cluster` and the pinned `ok-linux`;
  - the pinned Cilium 1.19.6 chart;
  - `release.txt` with both commits and the SHA-256 of the binary and the chart. (#499)
- **First run without internals.** (#502, and the `config show` and release-automation changes in this release)
  - `install-ok.sh` installs a bundle as a normal user: checksum first, safe extraction, verification, never overwriting anything.
  - `ok config init` finds and verifies the bundle and saves the management kubeconfig path. It never needs a provider kubeconfig for Same-Plane.
  - `ok config show` prints a readable summary with a live check of the running bundle; `-o json` keeps the machine format.

## Supported platforms

- macOS ARM64 and Linux AMD64 bundles.
- Runtime tools: Git, Make, Python 3 with PyYAML, kubectl, clusterctl, Helm. Go is needed only to build.

## Upgrade notes

- **New installs** go next to old ones; existing installations and `~/.local/bin/ok` are never replaced.
- **Destroy with the creating version.** Destroying a cluster with a different version than the one that created it is not supported: keep the creating bundle until its clusters are destroyed.
- **Existing configurations.** `ok-cli-paths/v1` (split-plane) files keep working. Same-Plane uses the new `ok-cli-paths/v2`, written only by `ok config init`, which never overwrites.
- **Scripts that parse `ok config show`** must use `ok config show -o json`; the default output is now human-readable.

## Known limitations

- Same-Plane Talos/KubeVirt on an already prepared management cluster only. Not a general installer and not production-certified.
- Artifacts are not signed, notarized or attested: verify the SHA-256 from a trusted channel. macOS quarantines browser downloads.
- Pod/service CIDR allocation uses local state only, so collisions are possible across operators. Cluster names can't be reused after destroy, because the teardown ledger keeps them.
- Only the tool versions used in acceptance were tested; no minimum versions are verified.

## Verification

```bash
shasum -a 256 ok-v1.0.1-<os>-<arch>.tar.gz   # Linux: sha256sum; compare with the published value
sh install-ok.sh --archive ok-v1.0.1-<os>-<arch>.tar.gz --sha256 <published value> --link
ok version                                    # v1.0.1 <tagged commit>
ok config init
```

SHA-256 values: *added when the release artifacts are built from the approved tag.*
